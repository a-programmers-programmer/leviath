and that absence looks contradictory next to the six hits above. It is not a
contradiction, and I checked before I claimed anything.

short line. It keeps the `collect ...` prefix and drops the rest of the string.
So the live artifact preserves the branch-identifying prefix but not the full
sentence. The prefix is sufficient: no other code path in `ceo_bus.py` emits
the words `no new runs since`. I confirmed that with:

    grep -rl 'no new runs since' /data/work/ceo-bus/*.py

"One file only: `ceo_bus.py`." That was wrong. The grep returns TWO files:

    /data/work/ceo-bus/ceo_bus.py
    /data/work/ceo-bus/_tick20260915T0229_persist.py

I diagnosed the second before adjusting anything, and it is not an emitter:

* mtime 2026-09-15 02:25:07 — LATER than all six skip files (newest 02:20:09),

* The match is at line 98, inside a markdown code fence inside the file's

* `grep -c 'cron/output'` on that file returns 0. Its only path write is

* It never references the job id `fbe1f00783b9`.

So the inference stands — the prefix still identifies the new `else` branch —
but the "one file only" wording was a false claim and is retracted here. A
successor re-running the grep will see two files; this note tells them the
second is a quoted copy, so they do not read it as a second emitter.

I record all of this so no successor reads a zero grep as evidence against the
