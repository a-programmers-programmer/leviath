## 4. What the implementation phase must do

Order matters. Do not instrument a spending path before the token and cost
fields exist.

1. **Lift the two contract files into the product repo.** They are the
   frozen interface. A shape change needs `v2`, never a silent field.
2. **Wire the mount.** Add `telemetry_mount.register(app)` in `main.py`
   after the OAuth guard is installed. One line. Rollback is one env var:
   `SITE_TELEMETRY_DISABLED=1`.
3. **Serve the beacon.** Copy `site_events.js` to the repo `static/js/`
   and add one `<script>` tag to `base.html`. No page content changes.
4. **Close `MeshGenerate` and `/api/publish`.** Both wait on the accepted
   GQL-01 envelope for run identity and the token/cost fields.
5. **Instrument the product `/graphql`.** Second hook, second mount, same
   contract. This is the honest half of the two-surface clause.
6. **Run one real synthetic browser workflow.** Headless, through
   `harness`-style isolation. Assert one `trace_id` spans UI, API and run
   events. Capture the JSON.
7. **Harden the salt.** `XELOR_TELEMETRY_SALT` must be set in the deployed
   environment. Without it the process falls back to a random per-process
   salt, which breaks cross-restart join. This is a deployment requirement,
   recorded here, not silently "good enough".
8. **Take the rollout overhead measurement.** Before and after, same
   machine, using the `perf-tools` measuring sticks. The `per_event_ms`
   number above is the input, not the answer.
